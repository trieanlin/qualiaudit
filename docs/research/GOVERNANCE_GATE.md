# Pre-recruitment governance gate

**This is not an approved ethics protocol or consent form.** It is a repository
checklist for the responsible study team. Do not recruit participants until each
applicable item has a named owner, evidence, and a local disposition.

## Study ownership

- [ ] Responsible study lead named outside the public repository.
- [ ] Institutional affiliation and applicable policy identified.
- [ ] Qualitative-methods advisor has reviewed both analysis routes.
- [ ] Human–AI interaction or automation-bias expertise has reviewed the claims.
- [ ] Accessibility responsibilities and accommodations route are assigned.

## Ethics and consent

- [ ] Required ethics review, exemption, or other institutional determination is
  documented by the responsible institution.
- [ ] Approved participant information, consent, withdrawal, and debrief
  procedures exist outside this repository.
- [ ] Recruitment and compensation are approved and non-coercive.
- [ ] Recording status is explicit; recording remains off if not separately
  approved and consented.
- [ ] The study avoids claims of diagnosis, ability, correctness, or validated
  reliance.

## Data minimisation and security

- [ ] Only the fictional synthetic QualiAudit project is permitted in tasks.
- [ ] Observation fields have been reviewed for re-identification risk.
- [ ] Recruitment/consent records are separate from session observations.
- [ ] Approved storage, access roles, retention period, deletion process, and
  incident response are documented.
- [ ] Completed notes, recordings, and transcripts will not be committed to
  GitHub or uploaded to QualiAudit/Vercel.
- [ ] No API key is required; the local deterministic reviewer is selected.
- [ ] No participant or real research data will be sent to a model provider.
- [ ] File naming uses a pseudonymous study ID, not a name or email address.

## Product and protocol freeze

- [ ] Exact QualiAudit commit and deployment URL recorded.
- [ ] Exact protocol version recorded.
- [ ] Synthetic reset and task order tested in a `DRY-RUN`.
- [ ] Browser/device support and requested accommodations tested.
- [ ] Network behaviour and provider state verified for the study build.
- [ ] Known limitations are included in participant-facing material where
  required.

## Analysis and reporting

- [ ] Codebook / Framework and Reflexive routes will be analysed separately
  before cross-mode comparison.
- [ ] No AI ground-truth, accuracy, or Reflexive Mode kappa measure is planned.
- [ ] Negative-case and protocol-deviation records are ready.
- [ ] Researcher positionality/reflexivity process is agreed.
- [ ] Publication plan includes null, negative, and contradictory findings.
- [ ] Product changes will cite evidence and retain reasons for non-change.

## Stop conditions

- [ ] Facilitators know how to stop a task if real data appears.
- [ ] Facilitators know how to handle withdrawal, distress, access barriers, and
  privacy/security incidents under the approved procedure.
- [ ] Unexpected transmission, misleading authority cues, or method
  misrepresentation triggers review before further recruitment.
